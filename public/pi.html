Device connection

Deploys pi-classic (Pi 0.74.2 adapted for BerryCore's QNX Node port) through the term49-web shell. The device builds nothing; npm runs on this host.

Installation steps

Work top to bottom. Each step unlocks the next; status updates from the device automatically.

0 / 7
1 Toolkit scripts pending

Adapter scripts (installers, curl transport, launcher wrapper) fetched from the bb10-classic-toolkit repository on the device.

2 Node zip pending

Pinned Node 22 for QNX/ARM, downloaded and SHA-verified on the device.

3 Node install (private) pending

Installs the verified zip into pi-classic/node/ — the Node build Pi actually runs.

4 Runtime package pending

Build on this host with tools/build-pi-package.sh, then pull from the app.

5 Launcher pending

Installs the pi command into BerryCore's bin.

6 Guard extension pending

File backups and confirmations for the agent (not a security sandbox).

7 Provider credentials pending

Copy BerryCloud's GLM endpoint or configure providers manually (one row per vendor). Existing configs are never silently replaced.

Checking for an existing configuration…

The API key is uploaded in base64 chunks through the term49-web shell and stored only in the device's ~/.pi/agent/ (mode 0600). It is not sent anywhere else.
