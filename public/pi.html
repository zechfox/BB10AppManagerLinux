Device connection

Deploys pi-classic (Pi 0.74.2 adapted for BerryCore's QNX Node port) through the term49-web shell. The device builds nothing; npm runs on this host.

Step 1 — Node.js

Pi uses its own pinned Node 22 (QNX/ARM, --jitless). The zip is fetched and SHA-verified on the device, then installed into pi-classic/node/. Installing the BerryCore node-term49 port is optional and separate.

node zip (pinned)—
node-term49 (qpkg)—

Step 2 — runtime package

Build the prepared package on this host, then let the device pull it. Build: tools/build-pi-package.sh (runs npm, transforms, tests, esbuild bundle; needs Node 22+ on the host). Serve: start the app with LISTEN_HOST=0.0.0.0 so the device can reach it.

Package installed—

Step 3 — adapter, launcher & credentials

Installs the toolkit's on-device scripts (curl transport, Unicode guards, launch wrappers), the pi command, the backup extension, and — optionally — copies BerryCloud's GLM endpoint into private Pi settings (on-device only, refuses existing configs).

Manual configuration — no BerryCloud needed. Writes the same models.json/settings.json as the toolkit's configure.py (same QNX compat settings), into the current terminal's home. One block per vendor — models from different vendors each keep their own endpoint and key. Switch models inside Pi with /model. Existing Pi configs are never overwritten.

Provider API endpoint API key Model IDs

The key is uploaded in small base64 chunks through the term49-web shell and stored only in the device's ~/.pi/agent/ (mode 0600). It is not sent anywhere else.

After installing, start Pi in Term49 with pi (resume: pi -c, pick session: pi -r). Startup takes about a minute on a Classic.
